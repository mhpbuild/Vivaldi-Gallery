# Contributing

Thanks for helping with this small hobby project. Please keep discussions kind, concrete and respectful.

1. Open an issue for a bug or substantial feature idea. Include reproduction steps, browser/device details and a screenshot when useful; redact personal data.
2. Fork the repository and create a branch. Keep each pull request focused.
3. Use Node.js 24 and `npm ci`. Run `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` before submitting.
4. For interface changes, check desktop and phone layouts, keyboard access, reduced motion and browser console errors. For 3D changes, keep `src/layout.json`, collision boundaries and Blender geometry aligned.
5. Describe what changed and how it was checked. Use normal branch pushes and pull requests; do not mirror-push or force-push the shared main branch.

Never submit credentials, personal files, `node_modules`, build caches or Blender backup files. Add media only when its provenance and redistribution rights are clear, and update CREDITS.md and ASSET_LICENSES.md. Preserve the noncommercial restrictions of the additional recordings. Do not add real payments to this demo without first replacing or separately licensing restricted media.

Original software contributions are under MIT; original media contributions follow ASSET_LICENSES.md. Third-party works retain their own licenses. Only contribute work you have the right to share. No contributor license agreement is required.

This is maintained in spare time; review and response times are not guaranteed. Report vulnerabilities through the process in [SECURITY.md](SECURITY.md), not in a public issue.
